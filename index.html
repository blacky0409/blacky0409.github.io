SYSTOR — Major Revision

Unboxing the Black Box:
Quantitative Analysis of Physical Fragmentation in Modern SSDs

SSLAB  ·  NVMeVirt  ·  SSD Aging  ·  Physical Fragmentation  ·  FTL
Overview

SSD를 오래 쓸수록 성능이 눈에 띄게 느려지는 현상의 상당 부분은, host 입장에서는 전혀 보이지 않는 physical fragmentation — 논리 주소(LBA)와 실제 NAND 물리 위치 사이의 어긋남 — 때문입니다. 문제는 이 physical fragmentation이 상용 SSD의 FTL 내부에 완전히 블랙박스로 가려져 있어 직접 관찰·제어할 방법이 없었고, aged 상태를 재현하려면 2TiB급 드라이브 기준 13일씩 실사용 워크로드를 반복 실행해야 했다는 점입니다.

본 연구는 NVMeVirt 기반의 고정밀 SSD 에뮬레이터를 확장하여, 에뮬레이터의 내부 상태(FTL 매핑 테이블, 블록 관리 구조, valid 데이터)를 스냅샷으로 캡처·즉시 복원함으로써 aging 과정을 수십 초로 단축하고, Pdegree·Lburst·Nstreams 세 파라미터로 physical fragmentation의 정도를 0~100%까지 정량 제어할 수 있는 Stochastic Physical Fragmentation(SPF) 모델을 제안합니다. 이를 통해 그동안 블랙박스에 가려져 있던 physical fragmentation의 성능 영향을 논리적 fragmentation과 분리하여 독립적으로 분석했습니다.

Key Contributions
01 / Emulation
FTL 내부 직접 제어 & 계측
매핑 테이블·블록 관리 구조까지 접근해 die collision latency/count 등 physical fragmentation 내부 메트릭을 최초로 정량 계측.
02 / SPF Model
Physical Fragmentation 정량 제어
Pdegree, Lburst, Nstreams 세 파라미터로 0~100% 재현 가능한 fragmentation 모델.
03 / Snapshot
즉시 Aging & 완전한 재현성
13일 걸리던 실제 디바이스 aging을 Valid-Only 스냅샷 복원으로 대체하면서도 결정론적 재현성 보장.
Key Results
13 days → seconds precondition 2.2× p99.99 tail latency increase QD=32 at peak vulnerability
Details

1. Snapshot 기반 즉시 Aging

스냅샷은 FTL 매핑 테이블, 블록 관리 구조(free/pool/victim block list), 디바이스 설정, 그리고 스토리지 전체 콘텐츠 네 가지를 캡처합니다. 초기 프로토타입은 저장·복원 대부분의 시간이 스토리지 콘텐츠 덤프에 소요된다는 걸 발견했고, 이를 valid 데이터만 저장하는 방식으로 최적화해 파일 크기와 처리 시간을 크게 줄였습니다 (128GiB 에뮬레이터 기준, utilization 20%에서 valid-only는 81초/28GiB, full dump는 173초/130GiB). 이 방식으로 2TiB 드라이브 기준 13일 걸리던 preconditioning을 수십 초 스냅샷 복원으로 대체하면서도, 실제 aged SSD와 유사한 열화 추세(SELECT QPS 기준 real SSD 97.9% 감소, emulator 99.1% 감소)를 재현함을 검증했습니다.

2. Stochastic Physical Fragmentation (SPF) 모델

무작위 데이터 재배치는 fragmentation 정도를 정밀하게 제어하기 어렵다는 한계가 있어, 세 가지 직관적인 파라미터로 모델을 설계했습니다: Pdegree(die 충돌이 발생할 확률), Lburst(충돌 1회당 같은 die에 몰리는 연속 페이지 수), Nstreams (동시 I/O 스트림 간 인터리빙 정도). 민감도 분석 결과 Pdegree가 성능 열화를 좌우하는 가장 지배적인 변수였고, Lburst는 구조적 심각도를, Nstreams는 상대적으로 완만한 2차 효과를 담당하는 것으로 나타났습니다.

3. 논리 vs 물리 파편화 분리 실험

실제 워크로드에서는 논리적 fragmentation과 physical fragmentation이 항상 동시에 발생하기 때문에, 이 둘의 영향을 분리하기 위해 2×2 실험 매트릭스(logical only / physical only / both / baseline)를 설계했습니다. 결과적으로 physical fragmentation만 주입했을 때(1,690 MB/s)가 logical fragmentation만 주입했을 때(2,803 MB/s)보다 훨씬 큰 성능 저하를 보였고, 두 요인이 함께 존재할 때(1,662 MB/s) 가장 낮은 성능을 기록해 두 차원이 독립적으로 작동하며 복합적으로 성능을 갉아먹는다는 것을 정량적으로 확인했습니다.

4. Queue Depth에 대한 반직관적 발견

fragmentation의 영향이 queue depth에 비례해 커질 것이라는 일반적인 예상과 달리, 실제로는 QD=32(die 포화 시점)에서 성능 열화가 가장 컸고, 오히려 QD=128처럼 과도하게 큐가 쌓이는 구간에서는 깊은 큐 자체가 collision을 흡수하는 버퍼 역할을 해 열화가 일부 완화되는 비선형적 패턴을 확인했습니다.

5. 실험 방법론 상의 발견: Host I/O 버퍼 파편화

초기 실험에서 동일 조건에서도 성능 편차가 매우 크게 나타나는 문제를 발견했는데, 원인을 추적한 결과 fio가 기본 malloc()으로 할당한 I/O 버퍼가 물리적으로 비연속적이어서(PRP 엔트리의 99.99%가 non-contiguous) NVMe 커맨드가 마치 심각하게 fragmented된 것처럼 처리되고 있었습니다. --iomem=mmaphuge 옵션으로 hugepage 기반의 연속 버퍼를 사용하도록 바꿔 이 노이즈를 제거함으로써(non-contiguous 비율 0.003%로 감소) 이후의 모든 측정을 신뢰성 있게 재현할 수 있었습니다.

Tiered Memory 구조를 위한 LSM Tree 개선 연구

한국정보과학회 KCC 2024  ·  LSM Tree  ·  Tiered Memory  ·  Hot/Cold Data Separation
Overview

본 프로젝트는 CXL(Compute Express Link) 기술 발전으로 도입된 Tiered Memory 환경에서, 기존 LSM Tree 구조가 가지는 성능적 한계를 분석하고 이를 최적화한 새로운 아키텍처를 설계 및 구현한 연구입니다.

[그림 1] CXL를 통한 Tiered Memory 구조

최근 빠른 주 메모리(Fast Memory)와 용량이 큰 서브 메모리(Slow Memory)를 함께 사용하는 환경이 대두되었습니다. 하지만 기존의 Monolithic 구조 LSM Tree는 데이터 검색 시 속도가 느린 서브 메모리까지 탐색해야 하므로 이러한 계층형 환경에서 I/O 효율이 급격히 저하되는 한계가 있었습니다. 저는 이러한 하드웨어 구조적 한계를 소프트웨어 아키텍처 개선으로 해결하여 안정적인 성능을 확보하고자 했습니다.

Details

1. Key-Value 분리 및 아키텍처 슬림화

문제를 해결하기 위해 WiscKey 논문에서 제시된 'Key sorting과 가비지 컬렉션의 Decoupling' 아이디어를 시스템 코드로 직접 구현했습니다.

[그림 2] WiscKey Data Layout on SSD

입력 데이터에서 Key와 해당 Value의 물리적 주소(Location/Offset 및 Size)만을 LSM Tree에 저장하고, 실제 데이터 용량의 대부분을 차지하는 Value는 별도의 로그 파일(vLog)에 순차적으로 Append하는 방식을 취했습니다.

  • 핵심 이점: Value 데이터가 트리에서 제외됨으로써 LSM Tree의 전체 크기가 획기적으로 축소됩니다.
  • 성능 최적화: 작아진 트리 전체를 접근 속도가 매우 빠른 주 메모리 상에 온전히 Cache할 수 있어, 검색 시 발생하는 서브 메모리 탐색 오버헤드를 완전히 제거했습니다.
  • I/O 증폭 해결: 압축 과정에서 무거운 Value 데이터를 반복적으로 이동시킬 필요가 없어 Write Amplification 문제를 근본적으로 최소화했습니다.

2. Tiered Memory 인지형 동적 Garbage Collection

두 번째 핵심 기술은 데이터의 사용 빈도에 따라 메모리 배치를 최적화하는 '동적 로그 파일 Garbage Collection' 파이프라인 구축입니다.

[그림 3] Log file Garbage Collection

로그 파일은 tail과 head 포인터를 이용해 신뢰할 수 있는 구간만을 엄격히 추적합니다. GC 가동 시 Valid가 입증된 데이터만 head로 마이그레이션하여 보존하고, 참조가 끊긴 Invalid 데이터의 점유 공간은 포인터 전진을 통해 즉시 반환함으로써 스토리지 파편화를 막고 공간 효율을 극대화했습니다.

특히, LSM Tree 상위 레벨로 밀려난 데이터는 상대적으로 사용 빈도가 낮다는 점에 착안했습니다. 따라서 GC 과정에서 Cold 데이터는 용량이 큰 서브 메모리로 마이그레이션하고, 자주 사용하는 Hot 데이터는 주 메모리에 남겨둠으로써 한정된 주 메모리 자원을 가장 효율적으로 사용하는 데이터 순환 구조를 완성했습니다.

3. 부하 테스트 및 실험 결과

NUMA 시스템 환경을 구축하여 30개의 스레드로 100,000번의 입출력을 발생시키는 고부하 테스트를 통해 성능을 검증했습니다.

[그림 4] 기존 LSM Tree와 개선된 LSM Tree 성능 비교

실험 결과, 모든 데이터가 주 메모리에 있는 'Best Case'와 서브 메모리에 있는 'Worst Case' 사이에서 약 20%의 성능 편차를 보이던 기존 구조와 달리, 새롭게 구현한 아키텍처는 메모리 계층에 관계없이 편차 없는 안정적이고 균일한 처리 속도를 입증했습니다.

NVMeVirt 다중 Instance 기능 및 성능 모델 개선 연구

한국정보과학회 KSC 2023  ·  NVMeVirt  ·  SSD Emulator  ·  Multi-Instance  ·  장려상 수상
Overview

차세대 스토리지인 ZNS SSD를 연구하는 데 있어 학계와 산업계는 보편적으로 NVMeVirt와 같은 커널 기반 에뮬레이터를 활용합니다. 하지만, 당시 NVMeVirt는 실제 하드웨어의 특성을 제대로 담아내지 못하는 치명적인 논리 오류와, 단일 디바이스에 종속된 아키텍처라는 두 가지 큰 문제를 안고 있었습니다. 구체적으로는 ZNS의 핵심 연산인 append와 write의 처리 시간을 동일하게 취급하는 오류가 있었고, 플래시 메모리의 물리적 특성인 블록 Erase 비용이 reset 연산에서 누락되어 시뮬레이션의 신뢰도가 현저히 떨어졌습니다. 또한 전역 변수에 의존하는 설계 탓에 대규모 시스템 환경을 모사하기 위한 다중 인스턴스 생성이 불가능했습니다.

Details

1. ZNS 성능 모델 재설계

저는 이러한 맹점을 해결하기 위해 가장 먼저 물리적 하드웨어 특성을 반영하여 ZNS 성능 모델을 재설계했습니다. 기존 시스템에서 하나로 묶여 있던 append와 write의 처리 파이프라인을 분석해 분리하고, 실제 디바이스에서 append가 write보다 지연 시간이 길다는 점을 반영하여 명시적으로 latency를 증가시켰습니다. 이와 더불어 Samsung 980 PRO의 실제 Erase Latency 스펙을 참고해 기존에 누락되어 있던 reset 연산 비용을 새롭게 구현했으며, 단순 지연이 아닌 연산의 실제 실행 시간까지 실측하여 합산하는 정교한 모델링을 완성했습니다.

2. 멀티인스턴스 설계

나아가 대규모 병렬 테스트가 불가능했던 단일 인스턴스의 제약을 허물기 위해 C언어 기반의 커널 모듈을 대대적으로 리팩토링했습니다. 단일 디바이스에 맞춰 정적(Static)으로 할당되던 리소스들을 모듈화하고, Global Variable에 의존하던 방식을 로컬 변수 기반으로 전환하여 인스턴스 간 메모리를 완벽히 격리했습니다. 컴파일 타임에 결정되던 설정 역시 런타임 동적 로딩 구조로 유연하게 변경했습니다.

동시에 기존 procfs로 동작하던 사용자 인터페이스를 sysfs로 개편하여, 사용자가 /sys/nvmevirt/config 디렉토리 하위에서 다수의 가상 디바이스를 독립적으로 생성하고 제어할 수 있는 체계적인 환경을 구축했습니다.

3. 결과 및 테스트

이러한 코드 레벨의 치열한 아키텍처 개선 결과, 기존 시스템 대비 최대 256개의 독립적인 가상 인스턴스를 동시 구동할 수 있는 압도적인 시스템 확장성을 확보했습니다.

fio를 이용한 벤치마크 테스트를 통해 수많은 디바이스가 동시에 I/O를 발생시키는 극한의 부하 상황에서도 성능 하락을 방어하며 안정적으로 동작함을 증명했습니다.

또한 성능 모델 재설계를 통해 IOPS와 Bandwidth를 실제 상용 ZNS 디바이스 수준으로 끌어올리며 시뮬레이터의 신뢰도를 대폭 향상시켰습니다. 단일 논문 작성에 국한된 성과를 넘어, 시스템 엔지니어로서 오픈소스의 근본적인 구조를 개선한 이 프로젝트의 성과를 인정받아 한국정보과학회 KSC 2023에서 장려상을 수상하는 쾌거를 이룰 수 있었습니다.

Overview

최근 개발 생태계의 화두인 Vibe Coding을 통해 실제 프로덕트 레벨의 앱 구현이 어디까지 가능한지, 그 한계점은 무엇인지 직접 검증하고자 시작한 실험적 개인 가계부 프로젝트입니다. Lovable 온라인 AI를 활용하여 수입/지출 입력, 카테고리별 통계, 월별 리포트 등 기본 기능을 구현했습니다.

Details

1. 바이브 코딩 분석: The Good & The Bad

단순한 앱 개발을 넘어, AI 툴을 활용한 개발 프로세스 자체의 장단점을 집중적으로 분석했습니다.

  • 장점 (기대 이상의 퀄리티와 구현력): 과거 AI 생성 결과물 특유의 투박함이 사라지고 상용 앱 수준의 세련된 UI를 도출해 냈습니다. 명확한 아키텍처 설계와 정교한 프롬프트가 뒷받침된다면, 구상한 대부분의 기능을 훌륭한 수준의 코드로 구현했습니다.
  • 단점 (최적화와 디테일의 부재): 기존에 작성된 코드나 컴포넌트의 맥락을 파악하고 효율적으로 재사용하는 능력이 현저히 떨어졌습니다. 특히 탭 간의 미세한 크기 조정, 비율 맞추기 등 사소하지만 UX에 직결되는 디테일한 레이아웃 구현에 취약했습니다. 결국 최종적인 디테일 Polishing과 최적화는 직접 코드를 수정하여 완성해야 했습니다.

2. Insights: AI 시대를 맞이하는 코더의 자세

논문 연구, 실험, 앱 개발 등 다방면에 AI를 적용해 보며, AI는 훌륭한 조수지만 아직 완벽한 대체재는 아님을 체감했습니다. 특히 정보가 방대한 일반적인 앱 개발 분야에서조차 'Optimization'와 '사소한 디테일의 완성'은 여전히 AI가 넘지 못한 벽이었습니다.

바이브 코딩 과정에서 "내가 직접 짜는 게 훨씬 빠르고 정확하겠다"는 답답함을 느끼기도 했지만, 이는 역설적으로 프롬프트 엔지니어링과 AI 활용 능력의 중요성을 깨닫는 계기가 되었습니다. 앞으로의 개발 생태계는 AI로 인해 일자리가 줄어드는 것이 아니라, 'AI를 완벽하게 통제하고 100% 활용하는 코더'만이 살아남아 더 큰 가치를 창출할 것입니다.

결론적으로 이 프로젝트는 단순한 가계부 앱 제작을 넘어, 개발자로서 AI라는 도구를 어떻게 지배하고 활용해야 할지 명확한 방향성을 정립해 준 의미 있는 실험이었습니다. 이러한 통찰은 이후 진행한 두 번째 프로젝트인 '스타일기'에서 폭발적인 개발 속도를 내는 밑거름이 되었습니다.
